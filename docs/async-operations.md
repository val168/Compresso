# Asynchronous operations

The main window runs each directory scan, compression, or restoration request on a dedicated `QThread` with one `OperationWorker`. Only one operation can run at a time. The path field, Browse, Analyze, Compress, and Restore controls are disabled while the worker is active. A Cancel button is shown for the duration of the operation.

The worker owns the scanner call or the compression backend call. The backend creates and waits for each `QProcess` on that worker thread, so process startup and file operations do not block the GUI. Progress, errors, and completed results cross to the window through Qt signals and queued connections; the GUI updates its widgets only on the GUI thread. Restore asks for explicit confirmation before starting.

When a worker finishes, the thread quits and the worker is deleted through Qt's deferred-deletion mechanism. A shared `std::stop_token` lets directory scans stop between entries and compression/restoration stop scheduling files. If `compact.exe` is active, the backend requests termination, waits briefly, then kills and reaps it if needed. The active file is reported as cancelled with an unverified final state. Files already completed remain changed; cancellation does not undo compression or restoration. Repeated cancellation requests are harmless. Closing the window requests cancellation and defers the close until the worker and any child process have exited. The destructor also requests cancellation and waits for the thread, covering shutdown paths that bypass the close event.

The compression and restoration workers report completed and total file counts, accounted logical bytes, elapsed time, and the current filename through a typed progress signal. The status text stays visible during work, and a one-second UI timer refreshes the elapsed duration while an individual `compact.exe` process runs. The standard progress bar is indeterminate while totals are unknown and changes to a determinate percentage only after enumeration provides a file count. Each completion increment follows an actual file result, including skips and failures.

The UI tests exercise scanner progress and cancellation, verify that a timer continues firing while a larger scan runs, and check that directory controls are disabled and restored around scans and compression. Backend tests cover successful, failed, skipped, and cancelled files, including partial compression and restoration cancellation.
