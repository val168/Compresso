# Native LZX compression

`compresso::CompressionBackend::compressDirectory` runs the Windows `compact.exe` utility once per accepted file with a structured argument list: `/C`, `/EXE:LZX`, `/Q`, and the file path. It does not invoke a command shell, create an archive, move a file, or rewrite file contents. The command uses transparent NTFS compression, so the files remain at their existing paths.

Before starting, the backend canonicalizes the selected directory and checks that it is not a volume root, a reparse point, a protected Windows location, or Compresso's own installation directory. It also requires a local fixed NTFS volume with the Windows file-compression capability flag.

Inaccessible entries, reparse points, files already compressed or using less allocation than their logical size, encrypted or sparse files, and files the operating system reports as busy are skipped. The backend also handles `compact.exe` failures per file. File identity, logical size, and last-write time are checked again after the command; a detected change is reported as a failure rather than counted as safely compressed. Each result retains the process exit code, stdout, stderr, and a concise error or skip reason. When NTFS does not retain LZX compression for a file and its allocation is unchanged, the result is skipped rather than reported as successful.

Restoration uses the same guarded target validation and file enumeration. Before invoking `compact.exe`, it calls `WofIsExternalFile` and selects only files backed by the individual-file WOF provider with the LZX algorithm. Standard NTFS compression, WIM-backed files, WOF XPRESS4K/8K/16K files, and files with multiple hard links are skipped. Skipping multiply linked files avoids changing the compression state of an alias that may be outside the selected game directory. For a matching file it runs `compact.exe /U /EXE:LZX /Q <file>` with a separate process argument list. Microsoft documents `/U` with `/EXE` as uncompressing executable-optimized files, while `/U` without `/EXE` targets ordinary NTFS compression; Compresso supplies `/EXE:LZX` and an exact file path so it does not use the broader NTFS-uncompress path or a recursive directory command.

After restoration, the backend verifies that the file identity and size remain stable, that WOF no longer reports LZX backing, and that a before/after SHA-256 digest of the readable file contents matches. A file that remains LZX-compressed or whose bytes differ is reported as failed. Files using another algorithm or whose WOF state cannot be queried are skipped without calling `compact.exe`. No file is moved or copied, and restored files remain directly accessible at their original paths.

The backend reports per-file outcomes because a valid NTFS volume does not imply that every file or every game is a good candidate. LZX is intended for read-heavy files; evaluate performance and compatibility for a specific game before applying it. No compression or restoration starts merely by selecting a directory or analyzing it.

Progress is based on the scanner's regular-file list and each file's returned outcome. The callback reports completed and total files, the logical sizes accounted for by completed files, the total enumerated logical bytes, elapsed time, and the current filename while that file is being checked or passed to `compact.exe`. Skipped and failed regular files count as completed once their outcome is known. Scanner entries without a measurable regular-file size are retained in the report but are not included in those file and byte totals. The UI remains indeterminate during target enumeration, then uses a percentage based on the actual completed-file count.
